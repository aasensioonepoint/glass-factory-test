# Codebase Indexing

This skill is the reusable body behind `$index`.

## Output Contract

- `CODEBASE_INDEX.md`: one-page architecture and entry-point map, generated by the builder. Modules table carries a `Depends on` column (coarse module edges) and per-module sizes, capped at ~15 rows. Only `Role` / `Owner agent` are agent-written, and they survive rebuilds. Header stamped `built @ <short-sha>`.
- `SYMBOLS.md`: stable IDs for routes, exports, schemas, classes, and migrations. Each line is `SYM-NNN  <path>:<lines>  <name>  <kind>  uses[SYM-…]  :: <purpose ≤10 words>` — the `uses[…]` edges make it a dependency map, not just a list. Header stamped `built @ <short-sha>`.
- the board (`TASKS.json`, or one record file per task under `tasks/`): one-object-per-task board (closed `state` vocabulary; several tasks may be `running` independently or in a group; `tasks.py parallel` proves disjoint declared write-sets before assigning a group — one active session per clone; worktree mode: `.agents/skills/task-board/SKILL.md`), tracked source of truth. `TASKS.md` is its generated, git-ignored table view. Written by `tasks.py`, never by hand.

## Rules

- Run the deterministic builder first: `python .agents/bin/build_index.py` (ctags — from `$CTAGS`/`$CTAGS_PATH` then `PATH` — with a Python fallback, incremental via the `built @ <sha>` anchor) writes `SYMBOLS.md`, `CODEBASE_INDEX.md`, `INDEX_DELTA.json` and `INDEX_BODIES.json` (one `body_sha` per live symbol, in a LATERAL file — the `SYM-NNN` row grammar never changes; the map is believed whole or not at all, keyed on the same `built @` generation). The agent only annotates `:: purpose` on `needs_purpose` and the `Role`/`Owner agent` cells on `needs_module_role`. Hand-extract only where the builder can't run.
- Start from manifests and existing index files.
- Use search before reading.
- Read complete files only when under 100 lines or when structure cannot be determined otherwise.
- Keep snippets out of the index.
- Prefer stable names and paths over prose.
- Record forward edges (`uses[…]`) to other indexed symbols only; derive callers by grepping the SYM id across `SYMBOLS*.md`. Never store reverse edges. Edges are name-matched — names carried by more than 8 symbols are dropped, and the same-file then same-module definition wins when a name is ambiguous.
- SYM ids are fixed-width within a build, so a grep for one id cannot match a longer one. Never hand-write an id at a different width.
- Shards are capped at 2000 rows; a large module splits into `SYMBOLS_<mod>_1.md`, `_2`, … with id ranges in the index-of-indexes. Read the TOC first, then only the shard you need.
- Generated and vendored files are excluded by the builder (`*.min.js`, `*_pb2.py`, `*.d.ts`, `node_modules/`, `vendor/`, `Pods/`, …) along with anything over 1.5 MB. **Et par FORME, pas seulement par NOM** (T-00000609) : un `.css` ou un fichier de la famille `.js` d'au moins 4 000 caractères dont la moyenne de ligne dépasse 200 est traité comme un bundle construit et ne rend **aucun** symbole. La règle de nom ne suffisait pas — mesuré, le bundle du kit s'appelle `ui/assets/app.js`, ne matche aucun motif, et pesait 2 051 des 7 807 lignes de l'index, soit 26 %. Le critère regarde **où sont les symboles**, pas où sont les octets : un module écrit à la main qui porte un gros littéral — SVG inline, police base64, sourcemap — garde les siens. La note d'exclusion part sur **stderr**, jamais sur stdout : `symbols.py --json` y écrit sa charge. Et un fichier ainsi écarté sort **NON COUVERT**, jamais `[GONE dans l'arbre]` : il est là, on a refusé de le lire.
- COVERAGE, exactly: `.agents` is excluded at **any depth** (L-020). In addition, in a tree the builder detects as a **vendored kit** — exactly one carrying `.agents/protected-paths.local` **or** `.claude/hooks/protected-paths.local` at its root — `.claude`, `.codex` and `.gemini` are excluded **at that root only** (`packages/x/.codex/` in a monorepo stays indexed). Under that same marker and at that same root, the kit's own CODE goes with them — **`agentic_v3`**, the V3 engine, which travels with the kit and would otherwise be counted as the consumer's own code; unlike a host directory it is **not** re-includable by `--unskip`, because it is never the consumer's code. The kit's own repository carries a NEGATIVE marker, `.agents/IS_THE_KIT`, and it WINS over either vendoring marker (checked first, presence only) — so there `host_skip_dirs` returns the empty set and all of those directories ARE indexed source. That marker exists because `.agents/protected-paths.local` stopped meaning only "consumer" (it carried the guard patterns of the local dev route from 2026-09-06 until that route was retired), and reading identity off it cost the kit 418 of its own 482 symbols before T-00000513 gave identity a signal of its own. It is `strip:`-ed in `.template-exclude`, so it never travels through the template channel: **if you find `.agents/IS_THE_KIT` in a project that is not the kit, delete it** — with it present your index treats your vendored kit plumbing as your own source. So: a hook, an agent-config file or an engine module has no symbolic entry in a consumer project — use glob/grep, it is not a stale index. **Migration note**: the exclusion set is fingerprinted into the header (`dirscope`), so an already-indexed adopting project that upgrades to a builder carrying a wider or narrower set pays for it exactly once — `--if-stale` sees the fingerprint disagree and runs one FULL rebuild instead of an incremental one, the same way a `--threshold` or `--kinds` change already forces one. Until that rebuild has run, `symbols.py query --strict` REFUSES with exit 3 (it judges the DB against the index FILES, and the files are what just moved) — that refusal is expected once per builder upgrade, not a break to chase; run `build_index.py --if-stale` (or `--resync` the DB afterwards) and it clears.
- Line ranges are hints valid as of the header sha; a reader must re-locate by name when the repo has moved on.
- Le moteur V3 peut vivre à `agentic_v3/` ou à `.agents/vendor/agentic_v3/`. Dans le kit, le second est sous `.agents/` : le recensement de l'index du kit le traite comme source. Dans un projet adoptant portant un marqueur de vendoring à la racine, le builder exclut `.agents/` à cette racine seulement. Ne conclure à une absence du moteur qu'après avoir cherché les deux chemins ; le nom du paquet Python reste `agentic_v3`.

## Index store (SQLite, per project — ADVISORY in v1) — repatriated from the router (P4)

Moved VERBATIM out of `AGENTS.md` so the router can stay thin. The router keeps the invariant and points here.

A project may additionally carry its index as a SQLite store, `index.db` (**schema v3**) — **MACHINE state, OUTSIDE the repository since T-00000668**: `state_project()/index/index.db`, resolved at ONE point, `cadre.paths.index_db`, to which both `migrate_index_to_db.db_path` and the wheel's `cadre.ledger.stores` delegate — built from the index FILES by `python .agents/bin/migrate_index_to_db.py` (`--check` plans and writes nothing · `--apply` creates · `--verify` round-trips · `--resync` re-runs idempotently, and upgrades a v1 or v2 store IN PLACE on the way — the rungs are climbed one at a time, so v1 reaches v3 in a SINGLE `--resync`). v3 adds one column, `body_sha`, fed from `INDEX_BODIES.json`; no key moves, so SYM-IDs, annotations, edges, journal and tombstones all survive the climb — the climb itself needs no replay; every `--apply`/`--resync` replays `annotations_log.jsonl` since T-00000668. A symbol's identity is `(path, name, kind, ordinal)`, where the ordinal numbers homonyms of one group by increasing start line — v1 keyed on the first three alone, which forbade the legitimate homonyms a single file may hold and made `--resync` REFUSE outright. **The start line orders, it never keys**: this identity is what re-pairs SYM-IDs across rebuilds, so a coordinate that moves with unrelated edits would reassign every id and break hand-authored annotations along with every `SYM-NNNN` reference from past sessions (L-00000138). It exists because a large repo's `SYMBOLS_*.md` shards make relational questions inexpressible and multi-shard greps unaffordable. **The placement IS the distribution rule**: the store lives in the machine partition, so it travels in NOBODY's git — neither the adopting project's nor `template/starter-kit` — and each clone rebuilds it with `--apply`: the `SYMBOLS*.md` files are versioned, and `annotations_log.jsonl` (versioned too) is REPLAYED into the store by `--apply`/`--resync`, so losing the store loses no authored annotation: per key, the store gets back the journal's last value of every field the files do not carry — a field the files carry is the files' own. A file left at the old path `.agents/state/index/index.db` is a LEGACY DUPLICATE: git-ignored, never read, named by a `NOTE: doublon hérité …`. **Outside a kit clone and without the `cadre` package installed, the SQLite index is ABSENT**: `symbols.py query/annotate/retire/compact` and `migrate --check/--apply/--resync` refuse naming `cadre.paths` (rc≠0), `build_index --stale-check` stays silent about the DB, and the `SYMBOLS*.md` files stay readable and authoritative — but everything only the store answers is LOST there: all of `symbols.py`, notably `--callers`/`--callees` (the reverse edges only the store holds) and `annotate`/`retire`, wherever neither the `cadre` package is installed nor `.agents/vendor/cadre/paths.py` (or, in the older layout, `src/cadre/paths.py`) sits in the clone. That is TODAY every starter-kit adopter, measured 2026-09-25: `origin/template/starter-kit` carries 0 files under `src/`, because it is synced from `main`, which carries 0 too (`src/cadre` lives only on the refonte branch) — and `.template-exclude` carries NO rule on `src/`, so whether `src/cadre` travels at the next sync depends on what `main` holds then, not on a rule. One capability is NARROWED, and said: a `.agents/` living in a SUBDIRECTORY of a git repository is refused (its resolved root is the git top level) rather than given a store of its own. The migration SCRIPT is tooling, lives in `.agents/bin/`, and travels normally.

The store is **ADVISORY, not authoritative**: `build_index.py` keeps writing the files, so the machine DB goes stale at every rebuild and no automatic `--resync` trigger exists in v1 — `--check`/`--verify` therefore compare `meta.built_at_sha` to the files' `built @` stamps and say `DB STALE` out loud (`--verify` exits non-zero). **That staleness is now SAID, unprompted, at the Stop nudge** (T-00000108): `build_index.py --stale-check` — the read-only probe that writes nothing and always exits 0 — asks `migrate_index_to_db.py` for the same comparison and prints a second, independent `DB STALE @ …` line, which `.claude/hooks/stop-reindex.sh` turns into a `systemMessage` naming `--resync`. Index files current and DB behind is the COMMON case, and it now speaks instead of hiding: measured on this repo before the change, the files were stamped `43e44a3`, the DB sat at `f483129`, and `--verify` was failing with nobody told. Saying it changes nothing else — still no automatic trigger, no resync, no marker file, no new SessionStart injection (the three session hooks discard the builder's stdout, which is precisely why the Stop nudge is the channel), and a DB that is absent, unreadable or `meta`-less degrades to silence rather than a guess. Bringing the store back in line stays a MANUAL, per-machine gesture: `--resync` — and **nothing to commit** but `annotations_log.jsonl` when it moved: the append-only journal that doubles the AUTHORED content (`:: purpose` per symbol, Role/Owner per module) and that `--apply`/`--resync` replay INTO the store after the files: a field the FILES carry wins; otherwise the journal's LAST value, a retraction included (the NULL row `retire` keeps is written) — decision S-00002394, which replaced the plan's "store first" merge because it never propagated a change or a retraction made on another machine, and `--verify` failed there forever. The journal merges `merge=union` (`.gitattributes`), so two branches that annotate no longer collide — and on a same key it is the ORDER OF THE LINES AFTER THE MERGE that decides. Measured (git 2.55): `git pull --no-rebase` (merge) puts YOUR lines first — upstream wins; `git pull --rebase` replays yours last — yours win; and `--resync` NAMES every stored value the journal's last line replaced (`NOTE: replaced by the journal's last value: …`, the first ten then the count), so the side that won is never silent. **BOUND, written rather than discovered**: the journal is folded once, when a `--resync` starts, so an annotation written by `symbols.py annotate` WHILE a `--resync` runs can be replaced by the old value; the next `--resync` restores it (its journal line is then the last). That journal is NOT part of the three stores the post-task-done hook commits. `.gitattributes` keeps the old path `binary`, a belt for a legacy duplicate someone would force-add. **A clone that ran `--apply`/`--resync` before T-00000668** — three cases, replayed in clones on 2026-09-25: store modified and NOT committed → `git pull` refuses ("local changes … would be overwritten", rc 1) and `git rm` without `-f` refuses too: `git checkout -- .agents/state/index/index.db` (or `git rm -f`), then `git pull`; modification COMMITTED → modify/delete conflict at `git pull --no-rebase` or `git pull --rebase` — a BARE `git pull` with no `pull.rebase` configured stops BEFORE the conflict (divergent branches, "Need to specify how to reconcile divergent branches", rc 128, nothing merged), so name the form: `git rm .agents/state/index/index.db`, then `git commit` (merge) or `git rebase --continue` (rebase — measured git 2.55: the emptied local commit is dropped by `rebase --continue`; an older git may ask for `git rebase --skip`). In every case THEN `--apply` at the new place (`--theirs` does not apply: on a modify/delete the remote side has no version). The migration never deletes a source file, and `CODEBASE_INDEX.md` stays the generated view read at SessionStart.

**Agents READ that store through one CLI, `python .agents/bin/symbols.py`, and RAW SQL STAYS FORBIDDEN to them** (T-00000107) — a hand-written `sqlite3 index.db "SELECT …"` bypasses, in one gesture, the output bound, the freshness check and the append-only journal. `query` searches by `--name` / `--purpose` / `--module` / `--kind` / `--file` and, crucially, walks `edges` BOTH ways (`--callers SYM-ID` / `--callees SYM-ID`) — the reverse-edge question the shards cannot express at all, since the files store forward edges only and say so in their own header. Prefer it to grepping `SYMBOLS_*.md` when the store is present and current (on a large repo the shards make that grep unaffordable and the relational question inexpressible); `annotate` / `retire` write an authored `:: purpose` or module Role/Owner into `annotations` AND into `annotations_log.jsonl` — `retire` APPENDS a retraction, it never cuts a journal line. On a field the index FILES carry, `annotate` and `retire` last only until the next `--resync` — a field the files carry wins (S-00002394) — and both SAY so (`NOTE: the index FILES still carry <field> …`, naming the `:: purpose`, `Role` or `Owner agent` cell to edit there too) — and `compact` tidies without ever deleting a tombstone, an annotation key, or an index source file. Output is bounded (`--limit`, default 40) and a truncation is always announced with the total; `--json` is the machine shape. **`--source` adds the body itself**: it slices `start..end` out of the WORKING TREE, prints a deterministic 0-LLM crux (`--source-lines`, default 8) and re-hashes what it read against the store's `body_sha`, giving `FRESH @ <gen>` / `DRIFTED @ <gen>` / `UNKNOWN` (the store holds no hash — pre-v3 or not resynced) / `MISSING` (file or range gone). **The verdict NAMES its reference** because the store is advisory: it compares the tree to the STORE, not to the index files, so when the store is behind a note says a `DRIFTED` may be the store's lag. Two different bounds, not one: `--source-lines` caps the SOURCE LINES of a crux, while the crux TEXT is produced for the first 20 result ROWS only (announced when it bites) — the VERDICT is computed for every row rendered. **Because the store is advisory it can be a generation behind, so every subcommand checks freshness** (the same comparison `migrate_index_to_db.py` owns): by default a `!! DB STALE …` banner heads the output and names `--resync`, and `--strict` refuses to answer at all (exit 3). Posture: default while exploring, since you re-locate by NAME anyway; `--strict` once the answer becomes code or a decision, and in any non-interactive consumer — knowing that `--strict` judges the STORE against the index files only; the tree question is the overlay's (below), so store-only bytes need `--no-refresh`, not `--strict`. An absent `index.db` is a named refusal pointing at `--apply` — never an implicitly created, empty database — and grepping the shards remains the fallback.

**THE FRESHNESS OVERLAY (T-00000378) — `query` NO LONGER ANSWERS FROM THE STORE ALONE, AND THAT IS A BEHAVIOUR CHANGE.** Before returning, `query` diffs the WORKING TREE against the store's own generation (`git diff <meta.built_at_sha>`), re-extracts the changed files with the builder's own extractors, and repairs the answer in flight. What you get back: **line ranges from the TREE**, marked `~moved(+8)` when they shifted and `~drifted` when the body itself changed — the two are independent and both are said, so a symbol merely pushed down by an insertion above it stops reading as an edit; `[GONE dans l'arbre]` for a symbol the store still holds and the tree no longer does; `[AMBIGU décalage ordinal]` for a homonym group whose SIZE changed between the store and the re-extraction, which is **refused rather than re-paired** because adding one homonym shifts the ordinal of every later one and a naive pairing would hand a new body to an old SYM-ID in silence; and a **`# HORS STORE` block** for symbols the tree holds and the store does not. Those never enter `results[]` and **never get an invented id**: either the index FILES already publish one (`SYM-207 (hors store — lancer --resync)`, the files being the authority) or the line says `(pas encore de SYM-ID — reconstruis l'index)`. `--json` carries the same facts machine-side, additively: a `refresh` object on the payload and an `overlay` object per row holding the STORE's original `baseline` bounds.

**It writes NOTHING** — no file of `.agents/state/index/` is opened for writing and the DB connection stays `mode=ro`; the property is pinned by a fingerprint test that carries its own witness. It is **bounded**: `--refresh-budget N` (default 40) caps the CHANGED FILES re-extracted, and a truncation is announced *with the names it left uncovered*; a negative value is REJECTED at parse time (argparse exit-2) rather than silently dropping files off the end of the sorted set. A changed file no extractor understands, or whose stored path escapes the root, is reported **NOT COVERED, never GONE, and never read** — "I could not look" is not "it is not there". Output is always UTF-8, regardless of the console's own encoding, so a `--json` answer survives a Windows redirect intact. **Four named causes make it unavailable** — the store carries no generation, the anchor is not hexadecimal, `git cat-file -e` cannot resolve it (the changed-file set would be partial *in silence*), or the published directory scope disagrees with this machine's — and each degrades to the baseline answer **plus the line naming which one bit**, never to a quiet one, because a mute overlay reads exactly like "nothing has changed". **`--strict` is ORTHOGONAL and no longer enough on its own**: it refuses a stale *store* (index.db vs the index FILES, exit 3) while the overlay answers the other question (the files vs the TREE). A non-interactive consumer that must have store-only bytes passes **`--no-refresh`**, or sets **`AGENTS_INDEX_NO_REFRESH=1`** for a whole session — and either way the answer SAYS it was disarmed, naming the variable when the environment is what did it, its value bounded to 64 chars on its own line (a hostile environment cannot drown the answer).

### § Golden rules — fraîcheur de l'index

- Index freshness has **three** deterministic (0-LLM) touchpoints — the post-gate rebuild above, a guarded refresh at session start on already-indexed repos, and **since T-00000593 the mid-task window between dev shards**, which this line used to name as uncovered: `dev_shard_reindex.py` runs on `SubagentStop` and rebuilds when the def that just returned is one of the three that WRITE code (`dev-mono`, `dev-multi`, `frontend-fidelity` — the closed set, `frontend-fidelity` included because it IS the dev slot on a UI task; `terraform-deployer`, the dev slot of an IaC task, is DELIBERATELY OUT, not forgotten: it writes `.tf` / `.tfvars`, a suffix absent from `build_index.py`'s `SRC_EXT`, so a rebuild after it would move no symbol — `dev_shard_reindex.py`, comment above `DEV_AGENTS`). Measured before being built: probe 0,29 s, incremental rebuild 0,43 s — cheaper than the notice it replaces. **Bounds, and they are not decoration**: it is ADVISORY and always exits 0; it never touches the advisory `index.db` (whose resync stays a deliberate gesture); it only repairs the staleness a rebuild CAN repair — the index is built from `git ls-files` alone, so untracked files leave it stale and the remedy is `git add`. **Coverage, to be cited as is: 1 MEASURED (Claude), 0 WIRED** — the file sits in `.agents/bin/` so the other registries CAN call it without a second copy, but none does today (`git grep dev_shard_reindex` returns one registration). The `indexer` agent itself remains a conditional, annotation-only stage (fills `:: purpose`/Role-Owner), never the freshness mechanism.
