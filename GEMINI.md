  **Reading — four lines are the witness, never the rc: `canary: 1` AND `yours refused: 0` AND `never read by the loader: none` AND `shadowed by a built-in agent: none`.** `canary: 1` is the refusal of `zz-canary.md`, a def invalid on purpose: without it NOTHING is proved — gemini missing (rc 127), wrong directory (rc 2), loading disabled, or a message reworded by an upgrade (the contract was measured on 0.57.0, printed beside your version). `yours refused: N` counts your defs the loader refused, each named on an `Agent loading error` line above, followed by the first line of its cause (a refusal can carry several, only the first is printed). `never read by the loader:` lists what the loader skips WITHOUT a word — subdirectories, names not ending in lowercase `.md`, names starting with `_`, symbolic links — neither loaded nor refused, so invisible to both counts; `.DS_Store` and `.gitkeep` are skipped as well but left out of that list, being expected there. `shadowed by a built-in agent:` lists the defs read whose `name:` is `generalist`, `codebase_investigator` or `cli_help`, the three built-in agents registered before yours: such a def loads, counts nowhere, and registration drops it without a word in `-p` mode (measured). Two bounds on that line: it reads the `name:` line of the first frontmatter block as text, not through a YAML parser; and `browser_agent`, a fourth built-in registered only when the browser agent is enabled (off by default, read in the 0.57.0 bundle), is not checked. A clean count proves the keys, not their values: `model:` is not checked at loading (`model: opus` loads, measured). `dummy key refused: N` (≥ 1) says the call took the dummy key; 0 says it went elsewhere. The rc is `1` nominally: loading precedes the API call, and TWO requests leave with the dummy key — a classifier (`generateContent`) then the turn (`streamGenerateContent`) — both refused (400, `API key not valid`); usage statistics to `play.googleapis.com` are switched off by `$D/defaults.json` through `GEMINI_CLI_SYSTEM_DEFAULTS_PATH` (measured: without it one POST leaves to `play.googleapis.com/log`, with it none). **It needs the network**: offline, the call stays silent for minutes and prints no count (measured: nothing after the version line for 240 s); an interrupted run leaves `$D` where `mktemp -d` put it — the block exports its own `TMPDIR` only afterwards — which on macOS is your `/var/folders/…/T` with the system `/usr/bin/mktemp`, whatever `TMPDIR` says (measured), and your `TMPDIR` with a GNU `mktemp` ahead on `PATH` (measured).

  **Isolation, variable by variable — it is what keeps those requests harmless.** `HOME` and `TMPDIR` are `$D/home`, and only `.gemini/agents` is copied, never your settings: with `security.auth.selectedType` (OAuth) in your `~/.gemini/settings.json` the dummy key would be IGNORED and a REAL call would leave under your account; your `~/.gemini/agents` stays out of the run too. It is `$D/home`, not `$D`: with `HOME` equal to the project the same folder loads twice, as user and as project, and the canary counts 2 (measured). `GEMINI_CLI_HOME` outranks `HOME` for the whole `~/.gemini`: left exported, the run reads the agents found there and writes history, `installation_id` and a session log into it (measured); emptied, nothing. `GOOGLE_GENAI_USE_GCA`, `GOOGLE_GENAI_USE_VERTEXAI` and `GOOGLE_GEMINI_BASE_URL` each outrank the key: with `GOOGLE_GENAI_USE_VERTEXAI=true` inherited, the dummy key is ignored and the run probes `metadata.google.internal` for your cloud credentials (measured). `GOOGLE_API_KEY` is emptied as a precaution, not for a measured leak: the SDK prefers it to `GEMINI_API_KEY` for a client built without an explicit key (read in the 0.57.0 bundle), yet inherited beside `GEMINI_API_KEY=dummy` both requests still carried the dummy (measured). `GEMINI_TELEMETRY_ENABLED` switches telemetry on from the environment: inherited with an OUTFILE or an OTLP endpoint, the run wrote the prompt and def names outside `$D` (measured: 176 444 bytes into the file, 436 512 bytes to a local endpoint); emptied, nothing was written or sent (measured). It does NOT outrank a `telemetry.enabled: true` in the system settings file — see the residual below. `GEMINI_SANDBOX` inherited: NOT measured. All of them are EMPTIED, not unset, and that is measured too: gemini loads the first `.env` found in `$D` or in any parent directory and fills only the variables that are ABSENT — with a parent `.env` setting Vertex, `unset` re-armed Vertex, the empty value did not. `pwd -P`: the loader prints the RESOLVED path, and on macOS `mktemp` answers under `/var`, a link to `/private/var`, where the filter would count 0. `cp -R .gemini/agents/.` into a real directory: a `.gemini/agents` that is itself a symbolic link is copied THROUGH, never linked — copying the link wrote the canary into its TARGET and left it there (measured); links INSIDE stay links, skipped as in your project. `set +e`: an inherited `set -e` stopped the run at `rc=1`, before any count and before `rm -rf` (measured). No value is ever re-parsed by a shell.
