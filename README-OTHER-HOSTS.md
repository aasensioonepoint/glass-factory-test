# Codex + GitHub Copilot + Gemini/Antigravity + Kimi Code Multi-Agent Kit

This is the companion guide for the four non-Claude-Code hosts in this repo. All four share one operating model with the Claude Code kit:

1. Keep durable guidance short.
2. Use an index as shared memory.
3. Detect the stack before coding.
4. Plan before edits for 6 files or more; a task of 5 files or fewer that `tasks.py direct` admits — the code VERIFIES it — goes straight to dev (`AGENTS.md`, « LA VOIE DIRECTE »).
5. Use specialized agents/skills for noisy or repeatable work.
6. Enforce safety with hooks where the host supports them.

Machine prerequisites (Python, git, per-host CLIs): see `QUICK-SETUP.md`. Scanner setup (NVD API key, offline mode, per-ecosystem tools): see `README-SECURITY-SCAN-SETUP.md`.

The kit ships 35 agents (24 core + 8 security + 3 closure critics) and is mirrored per host below. Each def has ONE source, `agents/<name>.md`, and each command ONE source, `commands/<name>.md`: the per-host agent folders, the roster `.agents/vendor/cadre/data/roster/`, `.claude/commands/` and the cross-host mirrors `.agents/skills/source-command-*` are rendered from them by `bash .agents/pyrun.sh .agents/bin/render_hosts.py --ecrire`, never edited by hand (`--check` names any drift of the flat files of these folders; a subfolder, a hidden file or another suffix is not read); `night` is Claude Code only and has no mirror.

## Workflows

- `$kickoff [-s true|false] <task>` — full pipeline (plan → approve → implement → security gate → docs → index). `-s true` (default) pauses on non-actionable dependency findings for a FIX NOW / ACCEPT & TRACK decision; `-s false` auto-records `pending_review` waivers without interrupting you.
- `$audit [-global]` — read-only, multi-module security audit; never edits code or the waiver register. Produces an HTML report under `.agents/state/local/sca-reports/` (plus a timestamped copy). `-global` adds a whole-repo application-security pass on top of the dependency scan.
- `$index`, `$skills-sync`, `$docs-sync` — refresh the codebase index; provision the detected stack (see below); and ingest `docs/tech/` respectively.
- `$kickoff --defer-night <task>` — approve a plan now without starting the dev stages, commit the plan snapshot (`docs(tasks): plan T-NNN`), then write the night-eligibility contract (plan snapshot + sha256 + linked critic verdict) while the task stays `pending`. The contract is host-neutral data, so this works here.
- `/night` — **not available on these hosts.** The overnight mode needs a session that can loop on itself or a hard spend ceiling (`claude -p --max-budget-usd`); Codex, Copilot, Gemini CLI and Antigravity expose neither, so `.agents/skills/night/SKILL.md` answers `COVERAGE DEGRADED — /night is Claude Code only; refuse autonomous overnight runs` and routes you back to `$kickoff`. It is a refusal by design, never an emulation. Deferred tasks approved here are picked up by `/night` in a Claude Code session.

Stack provisioning is driven by `.agents/ref/DOCS_REGISTRY.md` and shared by all hosts: it maps each language/framework to its official docs URLs and search hints for the OIDC-gated skills.sh probe, and holds an `installed:` ledger (id + hash). Best practices are pulled **dynamically and only when not already done** — `$skills-sync` (or the orchestrator, right after language detection) probes skills.sh per stack element (401 without a Vercel token, masked by the CLI as "No skills found"), falls back to the audited GitHub-pinned skills vendored under .agents/skills/vendor/ — the active GitHub fallback (`.agents/bin/skills_github_fallback.py`) is governed by the travelling policy `.agents/security/skills-fallback-policy.json` (`install_mode` ∈ {auto, confirm}, default `confirm` — `install` refuses rc 5 without `--confirmed-by <pilote>`, so the machine gate ships ARMED; a project opts into `auto` explicitly; `top` ≤ 2), installs at most one skill per stack element via skills.sh, at most two per stack via the GitHub fallback behind the mandatory AUDIT_LOG audit gate, and pins the hash into the ledger; a stack already provisioned is skipped. Dev agents then fetch the registry's versioned official docs *at need*, never pasting doc content into context.

## Pipeline

1. `$kickoff <task>` reads the board, read THROUGH THE CLI (`python .agents/bin/tasks.py list --json`, or `list --task T-NNN`): its store is `.agents/state/board/TASKS.json` OR one record file per task under `.agents/state/board/tasks/` — never hand-parse it, and `.agents/state/index/CODEBASE_INDEX.md`.
2. First the cadrage (cadrage_plan.py), read-only: its `CADRAGE <T>` … `FIN CADRAGE` block is relayed verbatim before the FIRST planner only (never on a resumption, a revision or a child of a cadrage cut), and `Verdict : découper` sends the task to its children instead (`.agents/skills/planning/SKILL.md` § Le cadrage). Then the language detector reads manifests and lockfiles only.
3. The skills resolver provisions the detected stack from `DOCS_REGISTRY.md` — dynamically and only if not already done (a stack present in the registry's `installed:` ledger is skipped).
4. The planner emits a concrete plan.
5. `plan-critic` reviews the plan read-only (verdict GO/GO_AVEC_RESERVES/NO_GO over a 7-row checklist); NO_GO sends it back to the planner (max 8 iterations in the kit; at an adopter, 2 by default, raisable on its pilot's explicit request — `plafond-critique=N` in `.agents/state/gates/PLAN_CHAIN_REQUIRED`, read by `plan_plafond.py`), then the plan stops for approval either way.
5b. Once the approval is traced on the task as the decision titled exactly `plan approuvé`, the session runs `python .agents/bin/tasks.py fournee <T>` — never a hand-run `tasks.py start` (`start` stays for `/night`, Claude Code only, for resumptions, and for the next child of a cadrage cut, after the MERGE of the earlier children it waits for (`.agents/skills/planning/SKILL.md` § Le cadrage), then `fournee` if its plan carries `LOT:` lines). It reads the plan's `LOT:` lines, creates one sub-task per lot, proves their write-sets disjoint, declares the parallel group and starts the parent and its lots; `--dry-run` previews and writes nothing, and a refusal lists every cause and writes nothing. A plan with no lot form runs as a degenerate batch: the parent alone. **On these four hosts the lots run in SERIES**: for each lot `git worktree add -b wt/<T-lot> <dir> <base>`, always from the SAME `<base>` (the main checkout's HEAD sha), the lots played one after the other; that the sub-agent keeps that cwd is NOT MEASURED, and the session says so with the line `COVERAGE DEGRADED — parallélisme des devs non mesuré sur <hôte> : lots joués en série` (per-host status and cause: § Parallel devs per host below, `.agents/ref/PARALLELISME_HOTES.md`). Only Claude Code launches the lots' devs in parallel, each in its own worktree, in ONE message (measured). Each lot comes back by `tasks.py retour` then `merge --no-ff`, its security verdict traced on the lot; the plan's `INTÉGRATION:` paths are written by the session after the merges, outside every write-set; ONE closing review and ONE gate cover the whole batch, then `done` of the lots, then of the parent.
6. A dev agent performs only the approved changes (a task admitted by `tasks.py direct` — 5 files or fewer, no guard path — skips steps 4-5b and keeps `exec-critic` ∥ the security gate (in parallel), the closing review, the gate and `done`).
6b. `exec-critic` ∥ the security agents of 7, IN PARALLEL on the same diff where the host launches subagents together (measured: Claude Code); elsewhere in series, exec-critic first, the fix still waiting for both verdicts: exec-critic replays every acceptance criterion with a real output; NO_GO returns to the dev, and every fix pass re-runs both (not the fix pass after the closing review).
7. Security agents gate the change, in parallel with 6b: code-review findings are always fixed, not waivable; dependency findings route through the waiver register per the `-s` flag above.
8. The documenter updates docs when the change warrants it.
9. The indexer refreshes `.agents/state/index/` when structure changed.
10. The closing review (`critic-opus`, fallback `critic-fable` then `critic-sonnet-max`) precedes the gate `bash core-scripts/verify.sh --at HEAD`; `tasks.py done` comes after both. NO TASK IS DONE WITHOUT A CRITICAL REVIEW.
11. The orchestrator's `FORECAST` (from `.agents/ref/TOKEN_BUDGETS.md`) is reconciled against actuals at session end; tune the budgets file when deltas recur.

## Parallel devs per host

Whether a host may launch a batch's devs in parallel, each in its own git worktree, is MEASURED host by host. The source of truth is [the measured per-host table](.agents/ref/PARALLELISME_HOTES.md): it gives each host's status (from a closed vocabulary compared by exact equality), the date it was established, the os-arch, the CLI version, the source or cause and the measures. A row holds for the workstation and version it was established on, never beyond. A host whose status is `mesure-parallele` launches the lots' devs in ONE message; every other status plays the lots in series, and the session says so with its host's `COVERAGE DEGRADED — parallélisme des devs` line (for `pas-mesure`: `COVERAGE DEGRADED — parallélisme des devs non mesuré sur <hôte> : lots joués en série`). `.agents/evals/test_parallelisme_hotes.py` checks that this link occurs once and that the table is not copied here.

The recorded causes are readings of the CLIs' help, binary bytes and sandbox profile; no third-party host model session was launched. The `claude` row's source describes worktrees launched together, without a measured timed overlap.

The batch launcher `.claude/workflows/workflow-fournee.js` travels with the kit but runs on **Claude Code only**, the one host with the Workflow tool. On Codex, GitHub Copilot, Gemini CLI, Kimi Code and Antigravity the session never calls it: it plays the same batch's lots in series as above. Its contract (args, statuses, losses) is in `.agents/ref/PARALLELISME_HOTES.md` § Le lanceur de fournée.

## Safety

Hooks provide deterministic guardrails for supported events on each host; they are not a complete enforcement boundary — the host's own sandbox and approval policy remain authoritative:

- protected path checks for `src/legacy/`, `generated/`, `.env*`, and credential-like files on supported Edit/Write/apply_patch payloads;
- skill installation audit gates for `npx skills add`, `pnpm dlx skills add`, `codex skill`, and `gh skill install`;
- shell guardrails for destructive `rm`/`mv` on tracked files;
- the SCA hooks now registered for all four hosts, sharing one deterministic entry point (`.agents/security/sca-scan.sh`, changed-files mode) run on the relevant pre-edit/pre-commit event per host;
- trusted session-start context injection from `.agents/state/` when the event payload is available;
- stale-index reminders after source changes;
- per-agent token capture on `SubagentStop`/`subagentStop` plus a session-stop est→actual recap, all into `.agents/state/local/RUN_LOG.md`; the agent-specific transcript takes priority, and everything degrades gracefully when a payload lacks usage data;
- **observability (canal A)**: each hook above also appends one JSON line to `.agents/state/events/` — a denial, a failed check, a stale index, a compaction, a session start, an agent's token total, a forecast reconciliation. Emission is *fail-open in the absolute sense*: if `.agents/bin/events.py` is missing or broken, nothing is written and the hook's stdout, stderr and exit code are byte-identical to a run without it (proved by `.agents/evals/test_events_parity.py`). Deleting `.agents/state/events/` breaks nothing.

### The `host` field on Codex vs Copilot

Copilot **executes the Codex hooks** (`.github/hooks/agent-guardrails.json` points its own events at `.codex/hooks/*.py`), so those files cannot tell from their own path which host is running them, and no payload field names the host either. The registrations therefore say so explicitly: they export **`AGENTS_HOOK_HOST`** — `codex` in `.codex/hooks.json`, `copilot` in `.github/hooks/agent-guardrails.json`.

Known limit, stated rather than hidden: if that variable is absent (a project provisioned before this was added, or a hook run by hand), the shared file leaves `host` **null** instead of guessing `codex`. Those lines land under `…unknown….jsonl` and show up as an unlabelled bucket in the dashboard's Coverage view — a visible hole, not a wrong attribution. `.gemini/hooks/` needs none of this: the label is read FIRST from the hook's own directory, through the closed table `{".gemini": "gemini"}`, so no environment variable can move it; only a directory outside the table (`.codex`, shared by Codex, Copilot and Kimi) falls back to `AGENTS_HOOK_HOST`. `.gemini/hooks/*.py` (excluding `test_*.py`, which each host keeps its own) is a BYTE-FOR-BYTE COPY of `.codex/hooks/*.py`: regenerate it with `python3 .agents/bin/hooks_jumeaux.py --ecrire`, which prints `ecrit: <name>` for each file rewritten; check it with `--check`, which prints `absent: <name>` / `different: <name>` / `orphelin: <name>` (an orphan, present in `.gemini/hooks/` only, is never deleted); never edit it by hand.

Because `.codex/hooks.json` changed, **Codex users must re-trust the hooks once** (`/hooks`) — the trust is hash-pinned.

Canal B (tokens, cost, model, durations) is the host's own OpenTelemetry stream and is opt-in per host: paste-ready blocks, including the mandatory `logPrompts: false` for Gemini and the machine-global-port caveat, are in [QUICK-SETUP.md](QUICK-SETUP.md) §7.

## Customize

- Add stack conventions to `.agents/ref/CONVENTIONS_<stack>.md` (shared by all hosts).
- Add project skills under `.agents/skills/<name>/SKILL.md`; Copilot-only skills under `.github/skills/<name>/SKILL.md`.
- Add custom agents as `agents/<name>.md`, then `bash .agents/pyrun.sh .agents/bin/render_hosts.py --ecrire`; a def dropped into `.codex/agents/`, `.github/agents/`, `.gemini/agents/` or `.kimi-code/agents/` with no roster JSON of the same name (`.agents/vendor/cadre/data/roster/<name>.json`) is outside the render (« hors rendu »): left intact, counted without its name by the `hors rendu : <n> fichier(s) …` note, it never blocks `--check` or `--ecrire`; only a def with the recognized header AND that roster JSON is an ORPHELIN, which stops `--ecrire` until `--retirer-orphelins` removes it. With a witness but no recognised header, outside `.cursor/`, it is ETRANGER: `--ecrire` writes nothing while it is there.
- Drop team docs into `docs/tech/<stack>/` and run `$docs-sync`.

## Notes

- `.agents/skills` is the shared skill location supported by all four hosts.
- `AGENTS.md` is the most portable instruction file for coding agents; `.github/copilot-instructions.md` and `GEMINI.md` exist so each host's native surface gets the same rules.
- Hooks are deliberately conservative. If a hook blocks a legitimate task, update the documented allowlist rather than bypassing the guard.
